Response-time analysis

Response is solved to a least fixed point for the single-core fixed-priority model. A task is proven schedulable when R ≤ D; a lower-bound result is a floor, not a proof.

R = C + B + I + ISR

Reference

Key terms

Short definitions for the concepts used above. The glossary is explanatory; the tables and timeline carry the actual results.

Task priority
QNX uses 0 for idle and 1–255 for threads; a higher number runs first. On a default procnto -P 63, priorities above 63 need PROCMGR_AID_PRIORITY.
Execution time (C)
CPU demand charged to one job, including modeled context-switch cost and service work performed on its behalf by channel servers.
Period and deadline
A periodic task is released every period; its relative deadline is measured from that release. Sporadic tasks use a minimum interarrival; aperiodic tasks use a mean and have no deadline guarantee.
Response time (R)
For this report, the analytical worst-case time from release to completion when the analysis can prove it; with unbounded blocking, R is a lower bound. The simulated Max column is one observed value from one deterministic schedule, not a general bound.
Worst-case response-time analysis
A fixed-point calculation that sums execution, blocking, higher-priority interference, and interrupt service. It is a proof under the stated assumptions when no blocking term is unbounded; it is not a measurement.
Priority inversion
A higher-priority task waits for a lower-priority task holding a shared resource. It is bounded by inheritance or a priority ceiling; without either, it can be unbounded.
Priority inheritance
PTHREAD_PRIO_INHERIT lets the holder of a mutex run at the priority of the highest-priority task blocked on it until it releases the mutex. QNX uses inheritance by default.
Priority ceiling protocol
PTHREAD_PRIO_PROTECT raises the holder to the resource ceiling while it holds the mutex. The ceiling must cover every task that can use the resource.
Missed deadline
The response time exceeds the relative deadline. A zero or missing deadline on an aperiodic task means no deadline guarantee is computed.
Slack
D − R for a task with a deadline. For a proven bound, positive slack is headroom; for a lower-bound result it is only a floor. Negative slack is the amount by which the bound misses.
Hyperperiod
The least common multiple of the periodic task periods: the repeating cycle for a synchronous periodic set.
ISR / IST
Interrupt service routines and interrupt service threads preempt application threads. Their entry and service time appear in the ISR term.

Scope

Assumptions and limits

The analysis is only as strong as these conditions. They are part of the result.

  • Single core: one thread runs at a time and priorities are a total order.
  • Durations are microseconds of pure CPU time on the target; measure them on hardware before trusting a bound.
  • QNX mutexes default to PTHREAD_PRIO_INHERIT; a mutex is only unbounded when the model says protocol: none.
  • A server inherits the priority of the client it is serving and keeps it after MsgReply, as QNX documents.
  • Interrupt service threads preempt every application thread; the clock IST runs at 254 and the IPI IST at 255.
  • Clock period 1ms, round-robin timeslice 4 ticks, context switch 2us.
  • Unbounded blocking: a shared mutex has priority inheritance disabled.

QNX boundary: this report is model output, not a target measurement. The QNX backend was compiled and run natively during Phase 3B; see docs/verification.md for the evidence and limits. No number here is a hardware timing claim.

Response-time bounds are analytical worst cases when the analysis proves them; a lower-bound result is a floor. The simulation is one deterministic schedule of the same model. A simulated latency above its bound is a modelling bug, not a nicer number.
