Concepts

The four ideas behind the result

The report defines these and more in its key terms. The short version:

Task priority
QNX uses 0 for idle and 1–255 for threads; a higher number runs first. Priorities above the unprivileged ceiling require an explicit ability.
Response time and deadline
R is the analytical worst-case time from release to completion when the analysis can prove it; a lower-bound result is a floor. D is the relative deadline. A task is proven schedulable only when R ≤ D.
Priority inversion
A high-priority task waits for a lower-priority task holding a shared resource. Inheritance or a priority ceiling bounds that wait.
Why simulation is not enough
One deterministic schedule can show a failure, but it cannot prove absence of one. The analysis supplies the bound; the timeline explains the mechanism.

What this project does not claim

No QNX SDP was available during verification. The QNX backend and image template are build-ready and source-reviewed, not compiled, booted, or measured on a target here. No QNX timing number is presented as a measurement. The host test suite and POSIX harness checks are real, and their limits are documented.
