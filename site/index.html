QNX OS 8.0 · Design-time scheduling analysis

Find timing bugs before the target does.

Scheduloscope models a QNX task set, computes a response-time bound, simulates the schedule, and generates a C harness for measuring the same workload on hardware.

v1.0.2 Apache-2.0 Node 20.11+ QNX backend: build-ready, not executed

Analyze

Fixed-priority response-time analysis with QNX-specific blocking, priority inheritance, interrupt interference, and context-switch terms.

Simulate

A deterministic discrete-event schedule with FIFO, round-robin, sporadic budgets, priority inversion, message inheritance, and ISR lanes.

Measure

Generate a C harness for the same model, with a QNX backend intended for on-target measurement and a POSIX backend for host compilation and CI.

Two backends, one explicit boundary

The analysis and simulation run on the host. The generated harness has two implementations with different evidence.

What this project does not claim

No QNX SDP was available during verification. The QNX backend and image template are build-ready and source-reviewed, not compiled, booted, or measured on a target here. No QNX timing number is presented as a measurement. The host test suite and POSIX harness checks are real, and their limits are documented.
